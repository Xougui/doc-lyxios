The **Surveillance** module is an advanced proactive security system integrated into Lyxios. Classified as a **private module**, it is strictly reserved for the project's bots and general administrators: the production bot **Lyxios**, the development bot **LyxiosDev**, **xougui** (owner and lead developer), and **kadawatcha** (manager and developer).

For obvious reasons of confidentiality, ethics, and global security, this module operates invisibly across all servers hosting Lyxios. It analyzes message streams in real time to detect, censor, and neutralize threats before they harm your communities.

---

## The Analysis Engine (Scanner)

Every message sent across monitored servers undergoes ultra-fast asynchronous scanning executed in a dedicated thread pool (`ThreadPoolExecutor`), ensuring zero latency for users.

The scanner performs a series of successive multi-level checks:

<Steps>
1. **Forbidden Words (`dangerous_words`)**
   Immediate direct detection of harmful or prohibited terms listed in our database.

2. **Phishing & Scam Regex Patterns (`scam_regex_patterns`)**
   Semantic regex analysis targeting recurring phrase structures found in fraudulent schemes (e.g., fake Nitro gifts, fake Steam giveaways).

3. **Obfuscation Detection (Anti-Bypass)**
   Spammers frequently try to bypass filters by inserting whitespace or special characters (e.g., `F r e e  N i t r o`). Lyxios automatically normalizes text using Unicode decomposition (Unicode NFKD), stripping accents and isolating alphanumeric characters to uncover hidden scams.

4. **Secret Leaks (Credentials Protection)**
   - **Discord Tokens**: Detection of accidentally leaked user or bot tokens. The bot validates the structure by decoding the Base64 portion (user snowflake ID) to avoid false positives.
   - **Webhooks & IPs**: Identification of exposed Discord webhook URLs and IP addresses.

5. **Heuristic & Advanced Phishing Analysis**
   For every extracted URL, Lyxios applies an in-depth risk scoring algorithm:
   - **Typosquatting**: Detection of domain spoofing targeting trusted platforms (e.g., `discord-gift`, `steam-comunity`).
   - **Levenshtein Distance & Similarity**: Computation of edit distance between scanned domains and official domains. Scores escalate if similarity exceeds 85% compared to `discord.com` or `steamcommunity.com` with an edit distance of 1 or 2 characters.
   - **TLD Weighting & Keywords**: High-risk keywords in URLs (`nitro`, `gift`) combined with suspicious extensions (`.ru`, `.xyz`, `.click`).
   - **Login Pages**: Detection of terms such as `login` or `signin` within URIs to flag fake authentication portals.
</Steps>

<Aside type="tip" title="Trusted Whitelist">
All official Discord servers and trusted domains (e.g., `discord.com`, `discord.gg`, `steamcommunity.com`) are cataloged in a global whitelist to avoid unnecessary false positives during legitimate discussions.
</Aside>

| Button | Button Style | Role & Behavior |

## Administration Commands

Alongside interactive alert buttons, bot administrators have access to dedicated text commands for moderation and contextual inspection.

### 1. Notify Server Owner (`!prevenir`)
Sends a professional, clear private message alert to the owner of the affected server.

* **Syntax**: `!prevenir <message_id> [raison]` *(alias `!p`)*
* **Features**:
  - Automatically identifies the guild owner.
  - Sends a structured summary detailing the detected threat with redacted content.
  - Includes a direct link to the message if still available.
  - Provides guidance and a direct invitation link to our support server.

```ini
; Command execution example
!prevenir 123456789012345678 Spam intensif de faux liens Nitro.

; Bot response
✅ MP envoyé à l'owner (ID: 987654321012345678).
```

### 2. Retrieve Context (`!contexte`)
Enables informed moderation decisions without joining the third-party server by reading surrounding messages before and after the alert.

* **Syntax**: `!contexte <message_id> [direction] [limit]` *(alias `!c`)*
* **Parameters**:
  - `<message_id>`: Alert message ID in the surveillance channel.
  - `[direction]`: 
    - `avant`: messages prior to the threat.
    - `apres`: messages following the threat.
    - `deux` *(default)*: surrounding history before and after.
  - `[limit]`: Number of messages to retrieve (`1` to `50`, default `5`).
